# 仿照CRISPR-GPT迁移：先拿到一套小而完整的结果

这是当前首要路线。用户的目标是迁移主参考文献的Agent工作方式，先跑通并取得可核查结果，再逐步补强；继续现有项目，不另建系统。先读[原文资料](../references/CRISPR-GPT/README.md)，然后按下面顺序做。只有真实外部阻断才需要用户介入。

## 这次迁移具体是什么

原文做“CRISPR实验辅助”，我们做“缺氧RPE / VEGFA siRNA候选核对与筛选辅助”。迁移三种模式、需求澄清、任务规划、状态机、工具证据、记录导出及任务评价。自有TPM作为细胞背景注释，暂不新增筛选权重。CNV作为背景；论文不声称当前系统已经证明CNV治疗效果或发现新siRNA。

原文系统用通用LLM，也加入了专门微调模型。我们先采用豆包API加工具与资料，这是明确的简化版迁移，不是原文完整复现。不要把原文288题、微调、所有工具和多基因湿实验都变成首批结果的门槛。

## 现在按顺序做

1. **先恢复一次真实模型调用。** 账号所有者核对方舟该模型的用量上限/安心体验模式，决定可接受额度。保留现有启动检查和手动评价。恢复后从现有网页“检测模型与联网”验证一次，保存实际状态；仍有账号阻断就停止，不反复探测、不自动加额度。
2. **先跑一例Auto。** 使用已支持的VEGFA输入，要求核对候选并结合缺氧背景给出报告。下载完整记录，核对模型实际选择了哪些步骤、工具是否成功、最终回答是否引用真实结果。说明OligoFormer/SeedMatchR目前导入经核对的历史输出，TPM不改变排名。无需等待重型模型云部署才能形成这一个有明确边界的案例。
3. **再开一批三组预评估。** 普通LLM、固定流程、Agent使用同一模型版本（适用组）、题目、数据和工具版本；固定流程和Agent具有相同的科学工具。每题3次，批次开始前保存协议。一次账号级阻断立即停批，保留已执行和未执行状态；新旧批次不得拼成成功结果。
4. **先统计能自动核查的量。** 原始状态、实际工具调用、证据覆盖、延迟和返回的token。缺失token保留未知；账号错误另列；停止是否正确须按预定答案判定。不要把调用成功率叫科学准确率。三次技术重复不等于三道独立题。
5. **独立评分之后再画质量比较图。** 先给每题配对结果、均值/分布和原始分数，不在6题开发集上制造泛化或显著性结论。固定流程与Agent之差可考察任务适配与异常处理；仅凭三组结果不能完全隔离“自主推理”机制。
6. **同步接上用户真实文献候选。** 用[空模板](../inputs/literature_candidates.template.tsv)录入原文序列与链方向。默认9条是计算候选池，不能代替用户文献siRNA。若湿实验采用候选池排序，应在看实验结果前冻结名单和理由；如沿用已知有效候选，则如实定位为流程可执行性案例。

首批交付包含：系统图、一例真实Auto记录、完整新批次及错误记录、自动统计表、独立评分后的三组比较图。专家未评分时先交原始答案和空白表，不伪造准确率。

## API暂时仍不可用时，照样交哪些结果

- 直接交现有系统图和9条候选核对图、自有TPM图及底层表，按[已有结果说明](../research/README.md)限定解释。
- 运行`python scripts/inspect_research_results.py`复核历史证据，不能把旧账号失败批次改成成功。
- 运行`python scripts/rebuild_candidate_report.py --output evaluation_runs/new_candidate_report`取得可复查的固定流程报告；这是无API、历史官方输出导入模式，不叫Auto新结果。
- 整理真实文献候选、完善题目和评分锚点；在阻断解除后继续第2步，不另起一轮框架重构。

暂不作为前置条件：专用模型微调、从零训练Transformer、扩大候选初筛、大规模扰动RNA-seq、动物/类器官、多用户产品化。新的论文结论依赖真实评价和实验；现有图不等于已经证明Agent更优。
