## 2. 与CRISPR-GPT的正确对应

重新核对[原文](https://www.nature.com/articles/s41551-025-01463-z)的Q&A评价段与Methods。原文写Q&A相对GPT-4o在准确性、推理和简洁性上分别改善12%、15%、32%；这些是其问答评价指标的对照结果，相关回答由专家评分。不能把这组数字说成“多答对12%的题”、实验有效率，或本项目的预期提升。

本项目可以采用“明确任务正确标准＋真实人工评价＋配对差值”的思路，量表沿用本仓库0–2分，不必为了接近期刊图而改成1–5分。原文百分比的具体归一化/差值口径若未从底表独立复算，不替作者补认定为相对提升或百分点。

## 3. 主要指标：有证据的任务完成率

每题运行前由真人审核必要交付项、关键事实、允许答案和严重错误。题目允许不同候选核查顺序时，不规定唯一优先候选。不存在实验真值时，评分对象是“是否正确完成规定辅助任务”，而非“是否找到了生物学最优siRNA”。

每个实际任务给出：
- 完成：所要求必要内容均交付，关键事实/序列正确，有可核查证据，没有会推翻本题结论的严重错误。
- 部分完成：有用但缺必要内容，或存在需纠正的问题；保留具体原因。
- 未交付：没有可用任务交付，如真实执行失败或只有无依据结论。

由真实评审给任务级判定；程序可以预标精确序列/数值及缺项，但不能用COMPLETE、工具调用次数、报告文件存在或四项分数的简单阈值自动代替判定。遇到有争议的严重错误由评审解决，不由LLM裁决计分。

**完成率＝被判“完成”的任务数÷该类别任务总数×100%。**部分完成在主指标中不算完整完成，不临时按半分抬高；其数量另列。因此三组都有同样定义的结果。

实际任务与需求变化分别统计，不混可靠性或问答：
- 实际任务完成率：如完整报告、限定参考/分数核对、证据比较。
- 需求变化完成率：一个多轮情景算一个任务；首轮满足原要求，补充后满足更新要求，且没有错误迁移旧证据，才算整段完成。另可记录“首轮失败后恢复”，但不能把最后一句正确替代全段表现。

若将来每题有技术重复，先算该题所有预定重复的平均完成比例，再对独立题目等权平均，不能给多跑的题更大权重。固定流程确定性只执行一次时，其这一题仍只有一个题目权重；不能复制它的答案当独立样本。每题重复三次仍只是一道题。

完整批次中真实尝试但无答案/报错的单元，在交付指标中保留为未完成；语义人工分仍可为空并写不可评分，不能把服务错误说成科学事实错误。尚未执行与实际失败分开；账号中止使批次不完整时，只报计划/已执行/未运行和已有描述，不把不完整批次包装成正式整体比较，也不剔除失败只算成功回答。

## 4. 关键事实交付与人工质量分

### 关键事实交付正确率：补充的可核查指标

每题预先列出必须交付的事实项目，如正确序列、参考坐标、覆盖、模型分数及定义、状态计数与来源；不把当前程序排序列作生物学真值。

**关键事实交付正确率＝正确交付的预定事实项目数÷该题要求的事实项目数×100%。**再按题等权平均，不直接混合全部事实以使项目多的题占更大权重。

每项分别标正确、错误、缺失；诚实说未知属于缺失，不能说成编造，但也不算完成数值交付。未要求的扩展内容不额外加分；其中出现的有害错误仍记录，防止用更多冗余内容掩盖问题。所需事实项目和容差须运行前确定：序列/整数计数精确，浮点数接受预定显示舍入。

该指标衡量规定事实是否被正确交付，不等于一般生物学知识准确率。它与主指标相关，不能当成第二个完全独立的“成功证据”。程序核对机械事实，证据含义和可接受建议仍需真人确认。

### 人工质量分：四项分别报告

沿用evaluation_rubric.json的四项：事实准确、证据支持、需求完成、边界处理，每项0–2分。由至少2名实际评审独立填写，报告各人的原分与分歧，按事先确定的办法处理。每题先平均适用的重复、评审评分，再对题等权汇总。

至少报告：
- 每组每一维的平均分及分布。
- Agent－普通模型、Agent－固定流程的原量表分数差。
- 实际评分题数、不可评分数和缺失原因；不能仅报“有回答子集”的高均分而隐藏未交付。
- 普通模型诚实说无法核查某分数，可以事实/边界正确，但该计算任务未完成；不能把它所有维度自动判零，也不能判成完整交付。

四项不先混成一个“科研准确率”。量表分是有序人工评价；优先报告原始分差，不将0–2分的相对涨幅当作科学概率提升。如果确需满分归一化展示，须写“占量表满分的比例”，而非“答对率”；不通过改变0–2/1–5起点制造漂亮的提升百分比。

文献问答按相同四维另表，先保证同工具组文库入口对等；不与实际任务合并。可靠性材料按预定正确处理判定列通过数/总数及错误种类，名称为“可靠性检查通过比例”，不称临床安全性或Agent智力准确率。

## 5. 差值与提升：同时写清基线、分母和单位

分别做：
1. Agent vs 普通模型：系统整体的工具/资料/规则支持差异；不能只解释为自主规划优势。
2. 固定流程 vs 普通模型：让工具本身带来的效果可见。
3. Agent vs 固定流程：同工具条件下的系统调度/交互与回答差异；不等于隔离纯规划能力。

主文对完成率优先报告百分点差：
**差值（百分点）＝Agent完成率－所比较基线完成率。**

二元完成比例可补充：
**相对提升（%）＝（Agent完成率－基线完成率）÷基线完成率×100%。**
基线为0时，相对提升未定义，不写无限提升；仍报原始比例及百分点差。结果为负如实写下降，不改题或改分母。

仅作算法说明的假设例子，**不是本项目数据**：完成率从60%到80%，是提高20个百分点，相对提升33.3%。不能只写“提高20%”而让读者猜含义。正式结果不使用此例，也不为它生成图表或数据行。

每个百分比旁至少给出n/N；重复运行则给独立题数、每题重复数和题均完成比例。对同题三组列配对结果，并报告Agent与各基线的胜/平/负题数；不能用互不相同的成功子集算差值。四项人工分的“胜/平/负”按维度定义，不能与二元完成标签混用。

小样本差值可很大，仍须显示分母与不确定性。未来若给95%区间，采用任务层面的配对方法；重复、评分者和同一母题变体不能当独立样本。题数不足时重点给原始配对表和描述性差值，不保证显著。12题是覆盖与工作量的务实目标，不是显著性或发稿资格的保证；不能为追求统计显著或更大提升事后加题/删题。

## 6. 严重错误与效率也要有数值

严重错误比例：由真人按事前定义标记“该题是否至少出现一项严重错误”，报告题数/总数。按类型另列篡改序列、套错版本、编实测数值、模型分数冒充百分比、无支持引用等；同一题多个错误不能伪装成多个独立题。

时间、模型请求数、实际token与人工操作另报，缺失用量保留未知。未验证收费口径前不换算人民币。固定流程无LLM请求可记0次，不等于整个软件/离线计算没有成本。云端导入速度不能当从头运行OligoFormer的速度。

比较质量和效率时，既看全部计划任务的失败/耗时，也可另列“同题两组均正确”的配对耗时；后者必须注明子集及其大小，不能只挑成功例声称整体更快。

若固定流程与Agent都正确且固定流程更省，就报告这项结果；若Agent只在需求变化更好，就把提升限定在该类任务，不能合并异常题制造总体优势。
