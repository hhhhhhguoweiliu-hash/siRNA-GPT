## 1. 先说结论

文章最值得检验的价值是：**在目前已支持的人VEGFA范围内，把研究人员的问题、真实序列和已有官方工具证据连接起来，交付可核查的辅助结论；信息补齐或需求变化后，能继续完成正确的任务。**

这比“懂多少siRNA概念”更接近实际用途。现阶段也只能支持这种有范围的应用主张：没有证据证明Agent发现了更有效的siRNA、能预测本体系实际敲低百分比，或在所有任务上胜过固定流程。

建议保留三类实际工作：已购试剂完整核查、限定范围的参考/分数核对、多项证据有冲突时的候选比较。另设需求变化任务；链角色澄清、错误输入及缺资料列可靠性专项；文献解释与无实测数据问答单列。**不凑九题，不把这些性质不同的结果合成一个“科研准确率”。**

草案方向基本正确，但还不是可直接运行的正式题包。必须修正：含答案的文件混入原始输入、固定路径由题目人工预选、共用多轮入口缺失，以及固定流程对部分任务的呈现不足。正式运行之前先完成无模型验收。

科研方向已明确，不需要用户再次决定“是否允许固定流程赢”。真正需要用户安排的是独立出题/评分人员，以及将来是否启动付费评价和预算。本次先完成离线工作，不等这些决定才整理材料。

## 4. 对用户N1–N6建议的逐项意见

这些是出题思路，不能沿用“Agent必对、裸模型大概率编、固定流程死穴”的预期。预期只能规定**三组共同适用的正确行为**，组间表现待真实数据决定。

| 建议 | 能否用 | 必须怎样改 |
|---|---|---|
| N1查SD_3499分数 | 可作标准分数核对，见W2b | 固定流程已有score路径，同样可准确给值。普通模型诚实说无法核查是边界正确，但计算任务未完成；不能事先判其必然编造 |
| N2 SD_3535与3499冲突 | 有用，并入W3 | 当前core.py已经把带复核提示者单列，并在无提示者中按分数排列，不能说固定流程只看高分。若题干已给分数和警告，三组都已获关键证据，应作为共同读表解释题，而非检索/规划优势题 |
| N3问实际敲低百分比 | 可作Q2同类边界题 | OligoFormer确实预测效力相关分数；准确说法是“没有将该输出转换为本细胞/处理条件实测敲低率的标定与实验数据”，不是“没有敲低预测工具”。三组都应区分预测与实测 |
| N4合法外观但坐标/物种错误 | 可作可靠性检查，见R3 | 坐标错误与物种错误分成不同材料，不能混在一题。当前verify_target按序列重比对，不保证检查用户任意新增坐标字段；小鼠来源序列也可能与人序列保守相同，不能仅凭来源或物种名断言不匹配 |
| N5只核对3499转录本 | 可作W2简化开发例 | verify_target依赖inspect_candidates，正确是完成必要检查及匹配，不是机械要求只调用一个工具。固定流程已有target路径，不能故意让它跑full |
| N6不给表达却要缺氧报告 | 有条件使用，见R4 | 网页内置表达表已存在，“用户没上传”不等于没数据。必须明确该题禁止使用内置表、且指定用户数据确实缺失。若评估工具不可用，要向两个工具组注入同一明确故障；共享错误处理不算Agent推理优势 |

N2有两个公平版本，必须运行前选定身份：一是不给模型分数、要求自行取得证据的W3；二是完整给出已有分数/警告、只让三组解释的读表题。不能把第二版当成第一版，或看到结果后择优报告。二者同属一个母题，不当两个独立研究问题。

## 5. 两项比较到底说明什么

| 比较 | 可以说明 | 不能说明 |
|---|---|---|
| 普通模型 vs 两个工具组，分别报告 | 在相同用户原始输入下，科学工具与绑定数据、规则和报告接口这一整套支持能否改善有证据的任务交付 | 不能把差别全归因于Agent自主推理；普通模型无法访问计算表时，也不能据此说其生物学知识较差 |
| Agent vs 固定流程 | 在相同工具、数据、资料范围和交互机会下，当前任务调度、解释与多轮实现是否有额外价值，代价多少 | 固定流程无LLM、Agent有多轮LLM，差别不只是规划；不能声称隔离了纯规划能力、同计算量优势或普遍智能提升 |

固定流程可包含确定性条件检查、按用户明确范围选取子流程、复用有效结果和提示缺项。它不必故意每题跑全套。其来源必须是运行前定义的通用规则，不是看某道试题或答案后人工指定正确工具路径。

建议默认采用三组共同可见的用户条件表，例如“对象/参考核对/分数核对/seed注释/表达注释/报告范围”；它表达用户要什么，不列正确工具顺序或答案。固定流程按这些条件走事先确定的规则。普通模型与Agent也得到同一条件表和原始用户文字。这样检验的是在明确条件下的系统交付，不能再声称比较了仅靠自由文字理解需求的能力。

如果保留人工选择preset的既有方式，必须叫“人工选择子流程的固定流程”，将人工选择及耗时计入，并向三组显示相同的选择信息。不能把它包装成完全自动基线，也不能仅给固定组额外答案。两种方式不能批中切换；优先做共同条件表的离线版本。

## 6. 原始输入、运行资源、评分底表必须分开

### 三种材料

1. **共同用户输入**：题干、原始候选行、原始订购两行和修饰、用户明确的计算假设及当前需求；三组逐字一致。
2. **运行资源**：固定参考、真实分数、seed表、表达表及允许文献。两个工具组通过相同接口取得。普通组按原设定不开放科学工具和外网；这是有意的系统条件差异，须明示，不能宣称三组证据访问完全相同。
3. **评审底表**：独立核对的坐标、计数、来源定位、允许答案、错误条件。只给评审与验收程序，不预先放进任一模型请求。

草案T01将订购README和sequence_records.json列作原始输入不够严谨：它们已经包含参考命中、链角色推导、是否在九条池中等核查结论。**原DOCX的两行及原注释可作为共同原始资料；sequence_checks、mapping、derivation、旧工具导出、旧最终回答、纠错文件、本复核的数值锚点不能偷偷随“输入附件”传入运行模型。**这些属于评审来源或显式先前证据。若某题本来要求解释已有记录，就将有关记录明确列为三组共同输入，并改变该题测量解释能力的定位。

原九条的原始候选表本来就有覆盖和设计窗口注释。不得选择性删除某组字段；转述原字段可算正确引用，不能算本轮独立比对。所有输入字段标明“用户提供/以前注释/本轮工具结果”。

科学参考文件是工具资源，不等于普通模型仅凭文件名就能读取。共同DOCX/CSV须先转成相同、可见的文本输入；不能只给普通模型一个私有链接，给Agent实际内容。大文件是否直接进入上下文、每组实际看到多少内容、截断及长度限制均在协议记录。

## 8. 三组运行协议的公平性要求

- 相同原始候选、序列、用户消息、条件表、文件内容、语言与适用输出结构。相同来源文本的截断策略；实际模型请求保存，不能只比较输入文件哈希。
- 固定流程与Agent共用科学工具、参考、导入结果版本、拒绝条件、缓存政策和检索来源。不能给Agent独享IRGM细节、文献原文或修复后的数据。
- 适用的两个模型组使用相同模型标识、思考设置、每请求输出上限、超时/重试规则与最终回答长度。系统提示词按职责不同可以不同，必须全部公开；共同事实边界和字段定义一致。
- 不声称同等计算预算：普通组通常每用户轮一次请求，Agent有规划/执行请求；固定流程无LLM。建议未来比较设置明确的每题时间、模型请求和工具调用上限，并完整记录实际值。若要声称等预算优势须另设计，本次不加新组。
- 多轮题对所有组同一轮数、同一补充信息；补充由预先脚本提供，不对某组临场提示正确答案。明确提问后触发的补充条件；不因某组先答错就私下补救。R1和U1可采用固定第二轮、所有组都收到的最简方案。
- 各题独立会话；题内保留各自实际历史。不得把前题的正确结论或审核说明塞入后一题。每组同样的会话长度规则，不偷偷清除固定流程/普通组历史。
- 冷/热缓存条件一致或分别标明。科学离线计算成本另列；云端导入耗时不能当OligoFormer全新推理速度。
- 统一匿名编号、输出栏目；保留原始文字与真实可交付附件。没有附件不能由评审从后台替其“补出报告”。相反，实际交付附件里的证据也不能因短答没重抄就全部忽略。
- 软件最终呈现与LLM原始文本分开保存。如果共享程序发现原答序列错误并标失败，要同时保留原错和展示状态，不能只用程序重排后的正确表格声称LLM回答正确。
- 运行顺序预先打乱，保存全部计划单元。固定流程确定性运行一次即可说明其输出；为测耗时重复时不能冒充多个独立答案。
- 暂未实现入口不计成某组科学回答错误，也不静默删掉。先标“尚未具备可比条件”，补齐后再另开将来获准批次。已经正式计划并发生的失败要完整保留。

## 10. 独立题目数量、人工评价与文章主张

### 建议规模及适用结论

建议将来以**12个经独立人员审核的不同任务情景**作为小型应用研究的目标：8个实际任务完成、4个需求变化情景。实际任务中包含完整核查、限定参考/分数核对和证据比较；保留固定流程很擅长的例子。这个数量是覆盖与人工工作量的务实选择，**不是已经做过功效分析得到的统计最低样本量**。

题数的前提是问题独立性审核通过：不能把同一结果换措辞、换top_n、换常/缺氧标签就凑满12。不同情景应有实质不同的输入证据、决策目标或变化条件，并标记共同母题、共同候选/事实来源。共享同一基因和同一工具链仍有相关性，不是12个独立生物学验证；统计按任务家庭说明限制。

### 人工评价办法

建议2名实际具siRNA/RNAi或相关生信经验、未参与代码与本轮调优的人员独立评分；分歧由第3人裁决或事先约定的讨论解决。优先让至少1人侧重实验解释、至少1人能核对序列/计算证据。若只能1人，称单人评价并列限制，不能叫独立专家共识。出题者与评分者若重合须披露，不把其题目熟悉度当盲法。

1. 开始前由真人确认每题必要事实、可接受的建议、严重错误和不确定部分。不能只有“应选当前程序前两名”的答案表。
2. 去掉组名与内部身份，打乱编号；评审先独立看原始回答、实际交付附件和必要来源，再评分。答案风格可能暴露组别，写“隐藏组名”而非保证完全双盲；不把含组别复核或private_key发给评审。
3. 沿用四项0–2分便于与既有开发标准衔接：事实准确、证据支持、需求完成、边界处理。2为充分满足，1为部分满足，0为明确错误/未达到；空白用于尚未评或不可评分并写理由。**不把两项/三项技术状态自动换成人工分。**
4. 每题另给任务级判定：完成/部分完成/未交付，及一条理由。完成须交付该题全部必要内容；可靠性题正确澄清/停止可算其要求完成，正常计算题仅诚实说未知不是事实错误，但计算交付未完成。
5. 严重错误单列，如篡改序列、套用错误版本、虚构实测值、把分数当百分比、引用不支持结论、把缺失填零。不能以文笔流畅抵消。评审核对输出，不通过阅读本文件替原答改正。
6. 单独自动核查字符串、数值、文件对应、计划单元和用量；这些只能辅助预标，不能给证据合理性/科研判断自动打分。显示舍入按预定精度接受，计数与序列不允许随意容差。
7. 时间、模型请求数、已知token及未知用量、人工选路/补充次数另报。两组回答同样正确时，低成本是有效结果；不以工具多/少直接打质量分。
8. 按实际任务、需求变化、可靠性、文献问答分别给每题配对结果和分歧。主要比较同一题的三组，不以“Agent成功次数占比”替代全部配对。若汇总，先每独立情景再按预定类别汇总，不让重复多的题权重更大；展示平局和不利结果。
9. 网络/账号等无可读回答时，语义评分不可评分；仍保留计划单元与未交付计数，不能剔除后只报成功答案。尚未执行的单元也保留；若批次因账号停止，整批不能称完整效果评价。已取得的错误回答仍由评审实际判，不用系统FAILED代填0。
10. 报告两名评审各自分数、分歧和最终处理。小样本以描述性配对结果为主，不在混合母题/重复的记录上制造显著性结论；如以后确需推断，须按独立情景/家庭处理相关性，另立方案。
