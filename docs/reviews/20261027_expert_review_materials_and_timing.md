## 什么时候邀请专家

**现在可以先邀请，任务是审题和确认判断依据；正式评分等真实三组回答与证据包齐全之后。**

- 现在：告知项目范围、预计工作量与安排，提供[给评审老师的项目说明](20261027_expert_briefing_ZH.md)、任务类型和量表，确认题目是否有真实科研意义、必要事实和允许答案是否合理。
- 运行前：独立人员审核/准备正式题目、所需事实与合理答案，版本、资源及评分协议确定。正式未见题的具体内容由独立人员保管，不用于执行端调试；若已给开发者调试，就标为已见开发题。
- 真实运行后：发完整匿名回答及证据包，两位评审独立填写；收回后按已有导入器检查并处理分歧，再计算三组实际分数与差值。

审题和正式评分是不同工作，须分别记录人员、时间、版本及修改。出题者与评分者若重合，披露角色；不要求为了这个小项目额外凑多名人员。评分者宜有siRNA/RNAi或相关生信经验，未参与代码实现/针对性调优；不必都具有教授头衔。人员安排和邀请由用户处理，本对话未联系任何人。

## 每题卡片必须让专家看明白

| 内容 | 必须展示 |
|---|---|
| 研究问题 | 为什么有实际用途；完整题干，多轮题包含所有用户补充 |
| 原始输入 | 原序列、来源、链角色假设、指定条件及输入已有注释 |
| 允许资源与范围 | 本题允许取得哪些数据、不能做哪些推断，资料缺项是什么 |
| 判断依据 | 必要事实、明确的来源定位、允许哪些合理结论；没有实验真值时不要给唯一“最佳siRNA” |
| 三份实际答复 | 匿名编号，与Excel一致；全文与实际交付附件可打开，不能用事后改写摘要替换 |
| 实际过程 | 每份答复实际执行的步骤、输入/输出、停止/澄清及每轮新增内容；不要求披露模型内部思维链 |
| 证据导航 | 关键结果→实际来源文件/行或片段→方法说明；预测、匹配、表达注释、文献与实验事实分清 |
| 评分位置 | 对应四维分、逐事实、完成判定和严重错误；不可评分的理由应能填写 |

不要求专家通读代码、全部日志或数百万行表格。主阅读页短而清楚，必须核对的内容逐项定位，完整原件作为可展开附件。摘要不代替原件，也不能给某份答案添加它实际未交付的证据。

预定主要评价对象是系统实际交付给用户的内容；模型原始文字与共享程序处理另留，以区分原答错误与软件防错。严格沿用前述协议，不把人工补充说明追溯算入模型答案，不把程序纠正当模型原文写对。

按普通任务、需求变化、可靠性、文献问答分册或明确标签；不要让专家误将软件输入拦截或Q1/Q2未接通当科研推理错误。三组同题采用相同必要事实标准；未取得证据如实计交付缺项，不事先把普通模型判为“会编造”。

## 分阶段验收

**审题版现在可交付：**项目说明、任务类型/科学意义、量表、逐题依据草案、练习题卡、人员工作与材料范围说明。当前事实标准和题包均标清开发/待独立审核；没有真实新回答的位置写待运行，不填示例分数。

**正式评分版运行后交付：**完整计划中的实际匿名答复与附件、逐题可回查证据、评分表、填写说明、分离的组别对应表。检查所有编号、文件与表格一一对应；失败原文保留，组别对应表不发评审。时序、提示词/资源和真实运行版本另存供方法复核。

独立性不能仅凭匿名编号保证：不发带组别/优劣判断的代码复核、修复讨论或成功预期给评分者，不在其独立填分前告知“哪个是Agent”“预期Agent更好”。方法与资料限制照实说明；文风或过程可能暴露来源，披露盲法限制，不假装完全双盲。

本文件不改变已定量表、题目范围或当前代码验收结论；不新增付费执行、模型训练或湿实验。没有真人评分，没有对外发信或联系专家。
