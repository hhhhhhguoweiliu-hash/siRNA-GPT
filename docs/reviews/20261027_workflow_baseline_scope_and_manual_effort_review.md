# 固定流程基线的解释边界与人工准备成本

日期：2026-10-27（北京时间）。所审结果及复核提交：`748a71bec7043fdd9b031731c237f687009f015b`；实际运行源码：`6c13c5788405e8ecf1aaf77144accd8108701d48`；结果原件：`4244ac0d9b9f0b1e01fe46f6871fd664825a4c24`。本次仅核对评价含义，不修改代码、原答、人工分数或图件，不新增模型请求。

用户指出：如果研究者已经替workflow整理证据和任务条件，却把准备工作算成workflow自己完成，会夸大其独立能力。这是本次需明确的限制；上一条仅以“固定流程擅长规则任务”解释评分高低，不够完整。

## 本次实际查到的实现

1. `evaluation_dialogue.py`的`fixed_plan(conditions)`读取预先给定的布尔条件，将`reference_check`、`score_check`、`seed_check`等映射成工具，并展开固定依赖。它没有在此步骤自行理解自然语言，亦没有在此函数按题号查人工答案。
2. 三组共同输入都带这些条件；Agent仍通过模型规划。共同给条件避免信息只给一组，但绕过了自然语言到所需检查项的一部分转换。因此本批不能验证“Agent从自由语言提取任务需求是否比传统入口省人工”。
3. `evaluation_contract.py`的`workflow_answer`把工具返回字段直接填表，并预写“模型分数不是敲低率”“匹配不是实测脱靶”等说明，近匹配记录则来自共同输入的`user_provided_evidence`。它不是现场自主收集、评价整套研究证据的模型。
4. `scripts/build_evaluation_development_pack.py`事先复制本地参考、历史预测、seed和表达等资产，规则写明两个工具组使用相同资源文件及工具接口；文献问答三组入口尚未接通。本批不能说Agent现场完成了这些资产的文献收集或重型计算，而workflow没有。

上述结论来自所列入口、模板与资源打包代码，不能扩大为对全仓库所有代码已完成答案泄露审计。

## 当前比较可以与不可以说明什么

可以：在准备好的VEGFA科学资产、结构化共同条件和规定工具内，比较两个配置实际执行、完整交付、证据呈现与失败处理。模板可以比模型自由转述更完整、更省；这些表现应保留。

不可以：据此认定固定脚本能自行理解任意科研需求、现场独立收集所有证据，或研究者使用workflow的全过程人工投入比Agent低。当前没有测量每题人工整理输入、选择检查项、修复数据、查证及解释所耗时和接管次数。科学资产的一次性准备也须与每次使用成本区分。

固定脚本读取文件、调用工具、条件分支、附来源及生成规则报告，均属合理能力，不能只因它不是Agent便人为删除。两个工具组本来应有相同的可用科学资料；不能让workflow手工寻找一份已直接提供给Agent的结果，然后将资料获取差异解释成Agent规划优势。若Agent具有真实可用的自动检索入口，应记录其实际检索、失败和用量后再比较；本批未运行的能力不能追补。

## 接续工作的最小原则

- 当前图和评分继续保留，注明“结构化输入与科学证据已准备的开发比较”，尚有评分理由与原答冲突；不直接称真实使用全过程更准确、更省人工。
- 如以后决定测量实际使用负担，应从同一真实请求和同一可用资料开始。workflow按其正常表单/参数入口使用，需要人填写或选择的步骤真实记录；Agent自行解析，错误同样保留。不能由作者给workflow每题额外整理所需工具清单，却将其算作无需人工。
- 科学资产的共同建设成本与每题人力分别说明；自然语言理解/任务选择、工具执行、报告字段完整、科学解释分开看。固定流程在标准任务上可以取胜，Agent是否省人工需实际测量，不预先承诺。
- 若想单独评价调度，两组可共享同一关键字段展示组件，再分别评价解释；这是未来新版本设计，不能用新模板替换本批旧模型回答或追改原分。
- 本次不启动新实验、不联系评分者、不新增付费批次，也不把讨论当作已批准扩大研究范围。是否补实际人力评价，由科研对话与用户按文章主张决定。
