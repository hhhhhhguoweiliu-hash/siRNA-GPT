## 1. 九条是什么，来源核到了哪一步

- 项目来源文档记载：2026-10-16将人VEGFA参考NM_003376.6的siDirect 2.0原始104候选整理成9条，10月18日用于原型。九条不是本批网页现场从用户RNA-seq新设计出来的，也不是已验证的文献siRNA。
- 已有序列、21nt双链/19nt核心、参考覆盖、历史分数、seed结果及来源指纹，前次核验可支持当前表格一致性和序列匹配。仅凭文件哈希与数值一致，不能独立证明最初科学程序执行和104→9筛选过程完整可信。
- 当前主仓库直接可读文件中尚未核得104行原始siDirect输出、提交参数和104→9逐条保留/排除明细；来源记录指向本地既有analysis和deliverable目录。不能断言那些材料在本地/Drive不存在，也不能直接把文档中的104→9说成已独立复核。
- cloud.py明确拒绝现场重算；core.py在imported模式核对候选与上下文后读取historical_scores.tsv和historical_seed_matches.tsv。因此网页快的已知原因是复用旧结果，而非当前重新跑完整OligoFormer。oligo_worker.py存在调用官方代码与权重的CPU适配路径，但存在代码不等于这次已执行；用户本地慢的具体原因仍需实际命令与日志。
- 自有RNA-seq的整理后表达背景已经打包到服务器。core.py实际将seed非靶基因与两状态TPM关联并计数；不用于九条初始生成，不进入OligoFormer，不改变默认排序。因此当前不能宣称完成“缺氧高效、常氧低风险”的经验证状态重排序。

当前用途：可作为固定开发候选池，检验序列核查、已有结果整合、表达注释及报告流程。论文可在补全来源后写“采用9条计算候选进行系统开发与流程验证”；不得写成9条实验有效序列、RNA-seq筛得的9条优选或Agent发现的最佳序列。预计算复用本身不等于伪数据；不能用这一点代替对最初来源的核验。

Codex应先回收已有原始输出、候选选择过程、科学工具输入/命令/环境/日志/输出，建立可检查来源链。缺失就列缺失，不事后编写筛除理由；确需重算时另建批次明确记录，不能覆盖旧54条或把新复算说成当年的原始运行。

## 2. 知识库和RAG的实际状态

knowledge.py只有6张人工写的项目说明卡，按标签关键词匹配。conversation.py问答会检索说明卡并放入模型上下文；research.py另提供PubMed题名/摘要、网页搜索及允许站点HTML读取（不支持PDF）。这是小型项目资料检索加联网查证，广义有检索增强雏形。

当前未完成领域文献PDF批量导入、正文切分/索引、论文段落定位与引用质量核验，也未建立覆盖领域的检索测试。仓库中保存参考资料不等于网站已经索引或会自动检索那些文件；联网查论文也不等于已建成本地全文知识库。54条工具开发题未证明文献问答或RAG效果。

科研判断：RAG（检索增强生成）不是所有Agent的必要资格，也不要求先收集所有siRNA文献；但若本课题要主张专业文献问答可靠，就要建立有明确范围、版本、来源与检索评价的证据库。建议从本项目实际用到的官方工具、序列规则、seed机制及RPE缺氧资料开始，而不是立刻无限扩库。此处是建议，尚未授权或完成新知识库实现。

## 3. Agent有哪些要素

用户提出的LLM、工具、记忆和规则是合理的拆法，另需说明目标/计划以及根据工具反馈继续、调整或停止的执行循环。

当前有豆包API模型；六项科学工具接口及检索工具；近期8–10条消息、计划、工具状态与来源记录；程序约束步骤依赖、输入和支持范围；有规划及受限工具执行循环。它比单纯聊天网页多出真实执行与反馈，但科学排序规则仍由程序预定，当前重型分数是旧结果读取，不能说模型自主发明了筛选方法。

记忆目前是会话/任务状态、文件导出及浏览器备份；不是经过验证的跨会话长期记忆或自主学习机制。服务没有可靠永久存储，不能把保存过日志说成系统能长期记住所有研究资料。

## 4. 数据到底放在哪里

- 已有内置RNA-seq：服务器读取随程序打包的整理表，并非网站实时读取用户C盘。
- 自带表达表：已有网页“表达背景与数据来源”上传入口。只支持不超过8MB的UTF-8基因级CSV/TSV，列为ENTREZID、approved_symbol、Nor1–4、Hyp1–4；不是原始FASTQ/任意Excel直接上传。新计划选定数据集，表达关联在后端执行；候选及相关工具结果可进入豆包上下文。
- 文献与RAG：没有通用PDF文献上传并自动建库接口；把PDF放进GitHub或贴Drive分享链接不会自动成为可检索知识库，需要另行实现读取、索引、检索和引用。
- 模型和参考：官方OligoFormer/RNA-FM权重及完整计算依赖需要放在实际计算机器；接了豆包API不会自动获得这些本地程序和文件。
- 本地访问：云端不能凭C盘路径或用户的localhost读取其电脑。已有本地app.py入口可在本机运行网页并通过API联系豆包；这不代表所有本地重型环境已实际验收。若保留云端网页而由本地电脑算，需要另外接通经认证的本地执行端，当前未实现该连接。电脑关闭后不能继续提供本地计算。
