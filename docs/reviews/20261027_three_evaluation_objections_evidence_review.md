# 对“字段核对、模板混杂、评分对象不一致”三项质疑的原件复核

日期：2026-10-27（北京时间）。所审任务分支提交 `c30473d3168ccf5ce6522722f0cea857c2065037`；实际运行源码 `6c13c5788405e8ecf1aaf77144accd8108701d48`，原结果提交 `4244ac0d9b9f0b1e01fe46f6871fd664825a4c24`，运行 `mini_real_20261027_061408`。这是LLM的证据与设计复核，不是新人工评分。

## 结论

三项意见指出真实的评价有效性问题：当前材料不足以把工具结果交付评分提升解释成“科研判断力更强”或“规划机制更优”。第二项的具体字节证据已复现，第三项的主答复/模型原文分离已复现。第一项应收缩主张，但不能据此否定真实官方工具输出的来源或把数值核对本身判为无价值。

此前指标交接可继续准备，但“多补评分、换成四指标”不能修复评价对象混杂。先落实本文件的对象划分和来源标签，再开展补充AI预评审。旧图和评分继续保留，暂作已见开发配置的交付描述，不作为Agent科研判断优越性的定稿证据。

## 1．字段来源一致性不是生物学真值，也不能覆盖全部科研判断

实际 `anchors.json` 有独立固定FASTA坐标查找、历史官方模型原行及用户提供的IRGM核查记录。`criteria.json` 同时要求解释：模型分数不等于实际敲低率，seed计数不等于实测脱靶，无警告不等于安全，以及供应商未确认的链角色不能当实物事实。因而说所有题目只是在抄数，范围过宽；但数值交付项目确实只能证明选对记录、绑定正确、引用无误。

用作者工具链输出同时作为待查结果与参考值，是工具集成/字段一致性检查，不能作为该工具预测真实效力的独立验证。官方输出可以作为“该模型本次实际输出多少”的正确依据，不能作为“这条siRNA实际敲低多少”的真值。这两类主张必须分开。

不扩大湿实验的修正方法：
- 数值核对保留为“结果获取、版本绑定和交付准确性”，标清原始来源、适用条件和独立复查范围。
- 若需要验证实现，应从原始官方结果、FASTA、原始seed明细或表达表直接复核转换/汇总，而不是仅用同一报表比对自身；抽查范围和未复核范围如实记录。无需另造评分算法或重算全部科学结果。
- W3/R1/R2/R4已有的证据解释、缺口判断和条件性建议另评，依据题干与原始证据/官方文献；允许合理多解，不按程序当前排名或模板用语判正确。它仍是有限已见案例的解释表现，不是一般科研能力验证。

## 2．A011与A025的1900字节完全相同，确为共用错误模板

已直接打开匿名原件ZIP，确认：
- `answers/A011/answer.txt` 和 `answers/A025/answer.txt` 均1900字节，SHA256均为 `5a8410ffa0b37136a59af3a60a000ef63356c306f530fa6585c6c9c94e3fa5b7`，逐字节相同。
- 两份 `raw_model_answer.txt` 均0字节。
- 两份匿名 `process.json` 递归比较只有 `/rounds/0/error_record/stage` 一处不同，分别为 `fixed_tools` 和 `executor`。
- 源码的 `run_dialogue` 异常分支统一设置 `SHARED_ERROR_PRESENTATION_NOT_MODEL_REASONING`，调用 `workflow_answer(..., error)` 展示已有结果与缺项。R4的最终文字不是两组各自撰写的模型报告。

但完整记录也显示：A011模型请求0次，A025模型请求6次。A025的规划和执行确实涉及真实模型，之后因缺表达数据进入共用错误报告。最终文字相同不表示整个过程相同，也不表示Agent全批答案均是模板。

全批33轮的来源与原始文字一致性见[逐轮来源表](../../research/2026-10-27_three_objections_audit/answer_origin_by_round.csv)。Agent共11轮，其中9轮原始模型文字与主交付相同，另两轮为A013被校验提示替代、A025共用错误模板。计数是轮次数，不是独立题数，也不直接代表正确率。

正确归因：
- R4可报告整套系统保留局部证据并阻止使用禁止数据；不能归功于Agent自主识别缺项或模型撰写了这份解释。
- 当前Agent与workflow同时有调度、回答生成及校验/错误展示的差异，因此总评分差不能单独归因到规划能力。共用模板在这题实际支持两组，而非只偏向workflow；其他正常任务的模板/自由生成混杂需一并标记。
- 同文同证据的纯答复维度应按同标准判断。若要评过程/成本则另开指标，不能把过程差异暗中混入文字评分。

## 3．A013的模型原文正确取到了分数，主答复却没有交付该值

匿名包的 `answer.txt` 为201字节，主答复是“模型序列检查未通过”的提示；`raw_model_answer.txt` 为844字节，包含 `0.9915144175887107`、来源及“不是敲低百分比”。原JSON也保存了两者。数字与同次工具记录一致；这是内部模型作答与实际主交付不同。

材料里已经有“不得用标准底表替答复纠错”等原则，但没有充分消除“模型原文已作为附录提供时，是否计入主交付”的操作歧义。不能说所有旧说明完全没规定，也不能假设所有评审实际采取了同一规则。另一个AI所说“差4分”尚未按同一份量表逐维复算，本轮不代定0分、2分或总分差。

今后的主分析建议明确：
- 主评价对象为实际用户可读的最终答复与明示交付的报告/数据附件，逐项列入范围；内部调试/原始模型文本另列诊断，不能无说明替换主答复。
- 单独评原始模型草稿时，结果标题注明“模型原文诊断”，不能与完整系统交付分混合。
- 对已有评审包，先记录各评审当时是否看/计入了原始文本，不能事后缩窄范围再宣称原评审按错规则。新口径作为单独回顾分析保留版本。
- A013属于有证据的软件误拦截案例；模型原文答对与系统交付缺陷可以同时成立，不把全部责任归为模型事实错误。
